# Evaluate complete Build candidates

A Build is evaluated as a complete Candidate: the builder finishes the plan, then the verifier and code reviewer evaluate the same result and combine their findings for correction. Checkpoints remain planning slices rather than separately budgeted evaluation units. We chose three builder attempts per explicitly authorized Batch, including the first, rather than independent retry budgets per Checkpoint, so the autonomous budget stays bounded as the plan grows and review includes the integrated result. Reserve a slot when the builder starts; incomplete implementation failures consume it, while environmental recovery and verification of unchanged code do not consume another slot. If three attempts still fail, Factory pauses with the work and findings preserved for the user to decide whether to continue. An explicit Continue or Request changes action authorizes a new Batch on the same Build and PR; ordinary comments do not reset the budget or start work.
