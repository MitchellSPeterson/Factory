# Domain modeling

Build and sharpen the project's domain model as you plan.

- Challenge vague or overloaded words. Propose one canonical term.
- When a term is resolved, write it into CONTEXT.md using that repo's glossary format. CONTEXT.md is a glossary, not a spec.
- Stress-test relationships with concrete edge-case scenarios.
- If CONTEXT.md already defines a word differently than the human, call that out.

Do not invent implementation details here. Names and boundaries only.
